# A workout on more than one device

How a running workout behaves when you're signed in on several devices, or have the app open in several windows. For contributors: read this before changing `ui/runner.js`, the run parts of `ui/sync.js`, or `users/<uid>/run` in `database.rules.json`. Checked on 25 Nov 2026 (#110). `test/e2e/devices.test.js` runs the cases that behave as they should in two browsers: stopping from a follower, stopping a workout whose device is gone, taking over the sound, a minimized follower when the workout ends, reopening later, signing out or _Reset all_ on the controller, and starting another workout while one runs elsewhere. A fix for a problem below adds its own case there.

## The model

**One workout at a time per account.** The account stores it as one small record, `users/<uid>/run`. Each device also keeps its own copy in `rf2_run`, so a workout survives a reload when you're signed out.

**The record holds start times, not a countdown.** It stores the step and when that step started (`i`, `s0`), when the workout started (`t0`), and the pause moment (`p`). Every device works out where the workout is from the clock. Times are on the sync server's clock: each device adds the offset Firebase reports (`rf2_dev.off`). That's why all devices show the same second, and why a workout keeps going while every screen is off.

**One device plays the sound: the controller** (`by`, its name in `dn`). That's the device the workout was started on or last controlled from. The controller says the cues, picks the boxing combos and writes the record when something changes. The other devices are **followers**: they show the same moment with no sound, and _Sound on Windows PC · Play here_ says which device has the sound.

**Touching a control on a follower makes it the controller.** Pause, skip, a tap on a tap-to-count step or a _Tap to start_ step, and _Play here_ all do this. The sound moves with it.

**The last write wins.** A write replaces the whole record; nothing compares versions. `u` counts up with each write. It is only used when a device reconnects, to decide whether its own copy is newer.

**How a workout ends.** `end` is `'stop'` or `'done'` (with `fin`, the finish time). The record is then left as it is. A record more than 12 hours old, or past its last step by more than 3 seconds, no longer counts as running (`runLive` in `core/engine.js`).

**The device code** (`rf2_dev.id`) is made once per browser storage and never sent anywhere except in `by`. Its name is a guess from the browser (_Windows PC_, _Android phone_). Two windows of the same browser share a code. Another browser, another browser profile, another address of the app (punchpace.app, the old addresses, each PR preview), _Reset all_, or cleared site data each give a new code.

### What each control does

| Control                     | On the controller                                                           | On a follower                                                                                                                 |
| --------------------------- | --------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Start                       | Starts the workout on every signed-in device, which follow it               | Same: this device becomes the controller                                                                                      |
| Pause / Resume, skip, tap   | Changes it everywhere                                                       | Takes over as controller, then changes it everywhere                                                                          |
| _Play here_                 | –                                                                           | Takes over the sound; nothing else changes                                                                                    |
| Stop (×)                    | Ends it everywhere                                                          | Asks: _Stop everywhere_ or _Just close here_. _Just close here_ closes it on this device only; the home screen still shows it |
| × on the home-screen banner | –                                                                           | Ends it everywhere, also when its device is gone (#114)                                                                       |
| Minimize (⌄, Back)          | Shrinks into a card on the home screen; it keeps playing                    | Same, silently                                                                                                                |
| Closing the app             | The workout goes on; followers keep showing it. Reopening picks it up again | Nothing changes for the other devices                                                                                         |
| Workout ends                | Shows the done screen and logs it                                           | Shows the done screen and logs it too. The log entry has the workout's id, so sync keeps one entry                            |

## Problems found

Each has its own issue:

- #117 Starting a workout while another device runs one replaces it without asking. Fixed.
- #118 After the controller signs out, the other devices keep the workout and log it as done, even if it was stopped. Fixed.
- #119 Changes made offline overwrite newer changes from other devices when the device is back online.
- #120 _Again_ on the done screen does nothing when the routine was deleted.
- #121 The same device under a new code reads as another device (_Paused on Windows PC_ on the PC itself).
- #79 Two tabs: also a signed-out second tab takes the workout over on reload (added to the issue).
